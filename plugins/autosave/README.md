# 文章自动保存 Autosave（YeCha 插件）

写给所有「写完一段、手一抖就没了」的人：编辑器在写作过程中**自动留底成多版本快照**，事后可查看、可载回、可手工删除。

## 为什么需要它

2026-09-10 的事故：编辑器「富文本 → Markdown」转换环节有缺陷，一篇文章保存后正文只剩空标题，正文文字全丢，而当时**没有任何可回滚的版本**，只能重打。本插件就是给这种情况兜底：**每次保存前留一版、离页留一版、写作中定时留一版**，且富文本模式下连 **DOM 原文**一起存 —— 只存转换结果是救不回来的。

## 留底时机

| 时机 | 说明 |
|---|---|
| 定时 | 每 N 秒（默认 30，可在后台改）检查一次，内容有变化才写一版 |
| 停手 | 输入后停手 5 秒写一版 |
| 切走页面 / 关标签 | `visibilitychange`/`pagehide` + `sendBeacon`，页面卸载也能发出去 |
| 点「保存」前 | 记录**按下保存那一刻**的正文，富文本模式另存 `rich_html` 原文，同时记录本次真正会提交的 `contentValue` |
| 手工 | 编辑器状态条上的「立即保存一版」 |

## 多版本与保留策略

- 每篇（按语言）保留最新 N 版，默认 **30**（3–500 可调）；
- 超过保留天数（默认 **30** 天，0=永久）自动清理；
- 后台可**单条删除 / 按篇清空 / 清理过期 / 清空全部**（清空需输入 `DELETE` 确认）。

## 保存在哪里（为什么不是 var/cache）

存数据表 `ye_autosaves`。**不存 `var/cache`**：框架 `Cache::flush('pages')` 会清空缓存目录，快照放缓存里等于一次清缓存就把"救命的多版本"清掉；快照必须活得比缓存久。表由插件迁移自动创建，卸载插件时一并删除。

## 怎么用

1. 后台「插件」页启用本插件（会自动建表）；
2. 打开任意文章的编辑页 —— 正文下方出现状态条：`自动保存已就绪（每 30 秒留底）· 历史版本 N 个 · 立即保存一版`；
3. 后台「文章自动保存」页可看全部版本：预览正文、**载回编辑器**（只填内容不写库，核对后再点保存）、删除；
4. 若某篇文章**库里的正文字数明显少于最近一次快照**（例如被清空过），编辑页会自动弹出醒目提醒，一键把那一版载回编辑器。

## 接口（管理员会话内）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/autosave/save` | 写快照（CSRF 校验；字段 cid/type/lang/title/slug/mode/reason/content/rich_html） |
| GET | `/autosave/get?id=N` | 取某版本全文（载回编辑器用） |
| GET | `/autosave/status?cid=N&lang=zh` | 版本数与库里可见字数 |

## 依赖

YeCha 核心需提供编辑器挂载点 `admin.editor.tail`（`core/Hooks.php` 的动作总线；`admin/posts.inc.php` 的 `pc_render_editor()` 末尾调用）。核心 1.0.0-beta.2 起已内置该挂载点。
